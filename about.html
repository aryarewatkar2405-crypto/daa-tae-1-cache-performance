01. Project Overview

In traditional algorithm analysis, data structures and search routines are evaluated primarily through asymptotic notations (such as Big-O, Big-Omega, and Big-Theta). These mathematical abstractions assume the Random Access Machine (RAM) model, which posits that accessing any memory address requires uniform, constant time O(1).

Modern computer architecture, however, violates the uniform RAM assumption. CPUs operate at clock frequencies orders of magnitude faster than main memory (DRAM). To bridge this throughput gap, silicon architectures implement a multi-tiered hierarchy of high-speed SRAM caches (L1, L2, and L3).

This laboratory provides an empirical framework to study how working-set capacity, memory layout, and cache locality influence real wall-clock performance when processing records that exceed estimated L1 and L2 cache boundaries.

02. Problem Statement

“Evaluate how cache misses affect asymptotic notations. Measure the performance of linear and non-linear array search structures when processing records that exceed the system's L1/L2 cache capacity.”

Students often misinterpret this relationship by assuming that hardware cache misses alter an algorithm's mathematical complexity class (for instance, falsely stating that cache misses turn an O(n) algorithm into O(n²)).

The primary objective of this project is to clarify that:

  • Asymptotic Complexity governs the mathematical growth rate of fundamental operations as N grows.
  • Cache Misses and Memory Latency drastically scale the constant factor and physical execution time, creating non-linear latency spikes when working sets spill across cache tiers.

04. Algorithmic Complexity Breakdown

We evaluate three foundational search paradigms representing distinct memory layouts:

Algorithm Best Time Average Time Worst Time Space Complexity Storage Mechanism
Linear Array Search O(1) O(n) O(n) O(1) auxiliary Contiguous TypedArray buffer
Binary Search (Array) O(1) O(log n) O(log n) O(1) auxiliary Sorted contiguous TypedArray
Binary Search Tree (BST) O(1) O(log n) O(n) (unbalanced) O(n) heap memory Pointer-linked node objects

The Constant Factor Difference

Consider a dataset of 100,000 records. A balanced BST requires approximately 17 node comparisons (∼ log2 100,000). A linear search requires on average 50,000 comparisons.

However, each comparison in a contiguous array reads sequential memory addresses that are already loaded into the CPU L1 cache line by hardware prefetchers. In contrast, each node comparison in a large BST traverses a heap pointer to a potentially uncached memory address, stalling the CPU pipeline for hundreds of cycles.

05. Cache Locality & Memory Architecture

CPU caches operate on fixed-size blocks called cache lines (typically 64 bytes). When a single byte is accessed, the entire 64-byte block is transferred from main memory into the cache hierarchy.

+-----------------------------------------------------------+ | CPU Core Registers | +-----------------------------------------------------------+ | (~0.5 ns, 1 cycle) +-----------------------------------------------------------+ | L1 Data Cache (32-64 KB) | +-----------------------------------------------------------+ | (~1-1.5 ns, 4-5 cycles) +-----------------------------------------------------------+ | L2 Cache (256-512 KB) | +-----------------------------------------------------------+ | (~4-6 ns, 12-14 cycles) +-----------------------------------------------------------+ | L3 Shared Cache (8-32 MB) | +-----------------------------------------------------------+ | (~60-100 ns, 150-250 cycles) +-----------------------------------------------------------+ | Main Memory / DRAM (GBs) | +-----------------------------------------------------------+

Spatial vs. Temporal Locality

Spatial Locality: If a memory location is referenced, nearby memory locations are likely to be referenced soon. Contiguous arrays exhibit maximum spatial locality.

Temporal Locality: If a memory location is referenced, it is likely to be referenced again in the near future.

When a search algorithm follows scattered pointers in dynamic heap memory (pointer chasing in linked lists or trees), it exhibits poor spatial locality. Each hop risks a cache miss, causing execution time to degrade dramatically once the tree working set exceeds the L2 cache.

07. Limitations & Technical Honesty

In accordance with scientific integrity, we explicitly document the constraints and execution characteristics of this browser-based performance laboratory:

  • No Direct Hardware Counter Access: Web browsers do not expose CPU Performance Monitoring Counters (PMCs) or hardware registers. The L1 and L2 capacities configured in this lab represent modeled experimental boundaries rather than direct silicon queries.
  • Just-In-Time (JIT) Compilation: The browser's JavaScript engine (e.g. V8, SpiderMonkey) dynamically optimizes bytecode, inline caches, and loop unrolling. We use warm-up passes to stabilize JIT optimization before timing.
  • Garbage Collection (GC) Pauses: Creating and traversing dynamic objects in heap memory (such as BST nodes) may trigger browser GC sweeps. We allocate datasets prior to the timed measurement window to isolate pure traversal time.
  • Dynamic Voltage and Frequency Scaling (DVFS): Modern processors dynamically alter clock speeds based on thermal headroom and OS load, introducing natural variance across trials.
  • Multi-Tenancy & OS Scheduling: Browser tabs run concurrently with operating system background tasks. Statistical multi-trial averaging helps smooth sporadic scheduling anomalies.

08. Conclusion

Asymptotic complexity remains the foundational language for classifying algorithmic growth. However, practical software engineering and performance analysis require understanding how algorithms interact with silicon hardware.

Contiguous memory layouts empower CPU hardware prefetchers and maximize cache line utilization. Pointer-linked data structures offer theoretical sub-linear search complexity, but incur higher per-operation latency when pointer chasing induces cache evictions across large working sets.
